# Cryptography

## Algorithms

| Purpose | Algorithm | Library |
|---------|-----------|---------|
| Signatures | Ed25519 (EdDSA) | noble-ed25519 |
| Hashing | SHA-256 | Node.js crypto |
| Key Derivation | HKDF-SHA256 | Node.js crypto |
| Password Hashing | scrypt (N=16384, r=8, p=1) | Node.js crypto |
| Random Generation | CSPRNG | crypto.randomBytes |

## Key Hierarchy

```
Org Root (Ed25519, KMS-backed)
    │
    ├── Gateway Signing Key (Ed25519, separate)
    │       │
    │       ├── Action Credentials (AR1 envelopes)
    │       ├── Approval Credentials
    │       ├── Delegation Registrations (verification only)
    │       ├── Passport Attestations
    │       ├── Blueprint Attestations
    │       ├── Revocation Feed Entries
    │       └── Checkpoints
    │
    ├── Checkpoint Key (Ed25519, separate)
    │       └── Audit Checkpoints
    │
    └── API Key Encryption (scrypt)
            └── API Key Secrets
```

## Envelope Format (AR1)

All verifiable credentials use `AR1` envelope:

```
AR1.base64url(header).base64url(payload).base64url(signature)
```

### Header
```json
{
  "alg": "EdDSA",
  "typ": "authragen+v2",
  "kid": "gateway_kid_1",
  "v": 2
}
```

### Payload (Action Credential)
```json
{
  "v": 2,
  "jti": "att_abc123",
  "kid": "gateway_kid_1",
  "issuer": "https://authragen.example.com",
  "subject": "agt_xyz789",
  "audience": "mcp:payments-svc",
  "iat": 1704067200,
  "exp": 1704067500,
  "intent_hash": "sha256...",
  "version": 2
}
```

### Verification
1. Split on `.` → 3 parts
2. Decode header → verify `alg === "EdDSA"`, `typ === "authragen+v2"`, `v === 2`
3. Decode payload → verify required fields present
4. Recompute signing input: `base64url(header) + "." + base64url(payload)`
5. Verify Ed25519 signature with org root public key (or gateway key for credentials)
6. Check `exp > now`, `iat <= now` (with clock skew)
7. Check `issuer` matches gateway
8. Check `audience` matches expected

## Canonical JSON

Used for `intent_hash` and envelope payloads:

```javascript
function canonicalize(obj) {
  // 1. Deep clone
  // 2. Sort object keys lexicographically (recursive)
  // 3. Serialize with:
  //    - No whitespace
  //    - No trailing commas
  //    - Numbers as-is (no scientific notation for safe integers)
  //    - Strings: NFC normalized, control chars escaped
  // 4. Return deterministic string
}

const intentHash = sha256(canonicalize(intent));
```

**Properties:**
- Deterministic across platforms/languages
- Rejects duplicate keys (throws)
- Rejects NaN/Infinity
- Rejects non-safe integers for amounts
- NFC normalization for strings

## Key Derivation

### HKDF for Key Separation
```javascript
// Org root → Gateway signing key
const gatewayKey = hkdf(
  orgRootKey,
  'authragen-gateway-signing-v2',
  32
);

// Org root → Checkpoint key
const checkpointKey = hkdf(
  orgRootKey,
  'authragen-checkpoint-v2',
  32
);
```

### API Key Hashing
```javascript
// scrypt(secret, salt, N=16384, r=8, p=1, dkLen=32)
const hash = crypto.scryptSync(secret, salt, 32, { N: 16384, r: 8, p: 1 });
```

## DID Format

```
did:authragen:<base64url(32-byte Ed25519 pubkey)>
```

- 43 characters (32 bytes → 43 base64url chars)
- Collision-resistant (full key)
- Resolution: exact match in passport store
- Legacy: 16-char prefix → best-effort resolution

## Nonce Requirements

- Minimum 16 characters
- Alphabet: `[A-Za-z0-9:_-./]`
- Generated by agent (not server)
- Single-use per org (persisted)

## Algorithm Agility

- Versioned envelopes (`v: 2`)
- Header `alg` field for future algorithms
- Current: Only `EdDSA` accepted
- Migration path: Add new `alg` with version bump
